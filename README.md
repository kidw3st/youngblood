# YOUNGBLOOD × Recording Studio

Сайт-визитка студии звукозаписи **YOUNGBLOOD** (Москва). Уличный, дерзкий,
граффити-дизайн: чёрный фон, жёлтый акцент, рваная бумага, скотч и спрей —
воплощено в живом, полностью кликабельном сайте с анимациями на каждом шагу.

**🔴 Живая версия:** https://kidw3st.github.io/youngblood/

---

## Что внутри

Сайт сделан по мокапам заказчика (6 экранов: Главная, О нас, Артисты,
Записаться, Расположение, Стайлгайд) и **полностью реализован в коде** —
это не нарезанные картинки, а настоящая вёрстка, которая воспроизводит
стилистику мокапов (цвета `#FFD600` / `#0A0A0A` / `#2B2B2B` / `#F5F5F5`,
граффити-типографику, рваную бумагу и скотч) средствами CSS/SVG, поэтому
всё остаётся чётким на любом экране и любом масштабе.

### Страницы

| Страница | Файл | Что на ней |
|---|---|---|
| Главная | `app/` (React) | Полноэкранный hero без скролла: видео-фон (boomerang-петля), логотип, навигация, заголовок, CTA, виджет «сейчас играет» с демо-битом |
| О нас | `about.html` | Принципы студии, фотоколлаж, комьюнити-блок, анимированные счётчики |
| Артисты | `artists.html` | Фильтр по жанру, живой поиск, сетка карточек, «показать ещё», модалка профиля |
| Записаться | `booking.html` | Рабочая форма записи с валидацией и анимацией успеха |
| Расположение | `location.html` | Адрес, как добраться, реальная карта, фотогалерея с лайтбоксом |
| 404 | `404.html` | Кастомная страница ошибки |

Главная страница — единственная, что собирается из React/Vite-приложения
(`app/`); остальные пять страниц по-прежнему чистый HTML/CSS/JS без шага
сборки. Подробности и обоснование см. в
`docs/superpowers/specs/2026-08-01-react-hero-migration-design.md`.

### Анимации и интерактив

- Прелоадер с анимированным логотипом
- Кастомный курсор (точка + кольцо), реагирующий на наведение
- Плавное появление блоков при скролле (`IntersectionObserver`)
- Параллакс декоративных элементов за курсором мыши
- Бегущая строка (marquee) с бесконечной прокруткой
- Анимированные счётчики статистики
- Скрывающийся/раскрывающийся мобильный бургер-меню
- Карусель артистов с drag-scroll и кнопками навигации
- Живой фильтр + поиск + пагинация артистов без перезагрузки страницы
- Модальное окно профиля артиста с «демо-битом» — да, кнопка play реально
  генерирует короткий бит через Web Audio API (осциллятор + шум), без
  внешних аудиофайлов
- Лайтбокс для фотогалереи студии
- Полностью рабочая форма бронирования: валидация обязательных полей,
  проверка телефона/e-mail, счётчик символов 0/500, анимация успешной
  отправки
- Кнопка «наверх», которая появляется при скролле
- Каждая ссылка, кнопка и карточка на сайте кликабельна и ведёт к
  реальному действию (переход по разделам, открытие модалки/лайтбокса,
  построение маршрута на карте, звонок/письмо, соцсети)

## Технологии

Главная страница — React + TypeScript + Vite + Tailwind CSS
(`app/`, собирается в CI). Остальные четыре страницы — сознательно
**без фреймворка и шага сборки**, чистые HTML / CSS / JavaScript, чтобы
открываться сразу и деплоиться «как есть».

- HTML5 (5 страниц + 404)
- CSS3: custom properties, grid/flex, `clip-path`, `IntersectionObserver`-driven
  reveal-классы, SVG-фильтры (зерно/шум через `feTurbulence`)
- Vanilla JavaScript (ES6+), один общий файл `assets/js/main.js`
  (кроме главной — она теперь на React, см. `app/src/`)
- React 18 + TypeScript + Vite + Tailwind CSS + `lucide-react` — только
  для hero-секции главной страницы (`app/`)
- Шрифты Google Fonts: `Anton` (заголовки, кириллица), `Rubik Wet Paint`
  (граффити-леттеринг логотипа YOUNGBLOOD), `Bad Script` (рукописные теги/жанры),
  `Inter` (текст)
- Карта — встраиваемый OpenStreetMap iframe (не требует API-ключа)

## Запуск локально

**Главная страница (React-приложение в `app/`):**

```bash
cd app
npm install
npm run dev       # http://localhost:5173
npm test          # юнит-тесты (Vitest)
npm run build     # продакшн-сборка в app/dist/
npm run preview   # предпросмотр продакшн-сборки
```

**Остальные страницы** (`about.html`, `artists.html`, `booking.html`,
`location.html`) — статика, подойдёт любой локальный веб-сервер
(открывать напрямую через `file://` не стоит — не заработают
`fetch`/маршрутизация путей для CSS/JS в некоторых браузерах):

```bash
npx serve .
# или
python -m http.server 8080
# или расширение "Live Server" в VS Code
```

## Деплой на GitHub Pages

Публикация автоматическая через GitHub Actions
(`.github/workflows/deploy.yml`): при пуше в `main` workflow собирает
`app/` (`npm run build`) и публикует результат вместе с нетронутыми
`about.html`/`artists.html`/`booking.html`/`location.html`/`404.html`/
`assets/` одним артефактом. **Settings → Pages → Source** должен быть
выставлен на `GitHub Actions` (не `Deploy from a branch`).

Файл `.nojekyll` уже добавлен в корень, чтобы GitHub Pages не пропускал
сайт через Jekyll-обработку.

## Кастомизация

Все точки редактирования вынесены так, чтобы не трогать вёрстку:

- **Цвета и шрифты** — переменные в самом начале `assets/css/style.css`
  (блок `:root`).
- **Артисты** (имена, жанры, био, статистика, треки) — массив `ARTISTS`
  в начале раздела 11 файла `assets/js/main.js`. Он один на весь сайт:
  из него рендерятся и карусель на главной, и сетка на странице
  «Артисты», и модальное окно.
- **Адрес и карта** — во всех `<iframe src="...openstreetmap.org...">`
  и ссылках «Построить маршрут» (`yandex.ru/maps`).
- **Контакты и соцсети** — в футере каждой страницы (телефон, почта,
  ссылки VK / Telegram / Instagram / YouTube).
- **Текст и изображения** — фотографии сделаны программно (CSS/SVG
  «тайлы» с шумом, силуэтом и виньеткой) без внешних файлов, чтобы
  сайт не зависел от стоков и весил минимум. Чтобы поставить реальные
  фото студии/артистов, замените `.photo-tile` на `<img>` в нужном месте
  разметки — все размеры и рамки уже настроены под фото 3:4 и 4:3.

## Важно перед запуском в продакшн

- **Ростер артистов** (FLEXY, MAYOT, YUNGWAY, LIL MORTY, 4N WAY, SEEMEE,
  GONE.FLUDD, LOVV66) и их био/статистика — демонстрационные данные по
  мотивам исходных мокапов. Замените на реальный ростер и фотографии
  перед публикацией.
- **Форма записи** (`booking.html`) сейчас работает полностью на
  клиенте: валидирует поля и показывает анимацию успеха, но никуда не
  отправляет данные — нет бэкенда. Чтобы заявки реально приходили вам
  на почту/в CRM, подключите один из вариантов (без сервера):
  - [Formspree](https://formspree.io) — добавить `action="https://formspree.io/f/xxxxx"` в `<form id="bookingForm">`;
  - [EmailJS](https://www.emailjs.com) — отправка письма прямо из браузера;
  - свой бэкенд — заменить обработчик `submit` в `main.js` на `fetch(...)`.
- **Соцсети** сейчас ведут на корневые домены (vk.com, t.me и т.д.) —
  замените на реальные страницы студии.
- **Демо-бит** в плеере артиста — это синтезированный звук для
  демонстрации интерактивности, а не настоящие треки. Чтобы подключить
  реальные записи, замените вызов `playBeat()` в `main.js` на
  `new Audio('путь/к/треку.mp3').play()`.
