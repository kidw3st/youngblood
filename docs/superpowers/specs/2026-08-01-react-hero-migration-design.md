# YOUNGBLOOD — миграция hero главной страницы на React + Vite + TS

Дата: 2026-08-01
Статус: approved (design), реализация не начата

## Контекст

Сайт YOUNGBLOOD (студия звукозаписи, граффити/уличная эстетика, палитра
`#FFD600/#0A0A0A/#2B2B2B/#F5F5F5`) сейчас — 5 статичных HTML-страниц без шага
сборки, задеплоенных на GitHub Pages "как есть" (branch `main`, root). Это
сознательное решение, зафиксированное в README.

Пользователь прислал технический спек стороннего проекта "quietpress"
(винил-лейбл: React + TypeScript + Tailwind + Vite, lucide-react,
boomerang-видео фон через canvas, `.liquid-glass` эффект, fade-up анимации,
виджет "Now Playing") и попросил сделать сайт "как этот, только с моей
информацией".

Визуальный язык референса (белый/синий `blue-700`, Helvetica, спокойный
минимализм) прямо противоречит утверждённым заказчиком мокапам YOUNGBLOOD
(чёрный/жёлтый, кисть/спрей, рваная бумага, скотч). В брейнсторминге с
пользователем прояснили:

- Берём **только техническую механику** референса (boomerang-видео, liquid
  glass, fade-up), перекрашиваем/переверстываем в граффити-палитру
  YOUNGBLOOD. Стиль quietpress целиком не копируем.
- **Мигрируем стек** hero на React + Vite + TS (несмотря на то, что это
  меняет архитектуру проекта и требует шага сборки).
- **Объём — только hero главной страницы** в этой итерации. Остальные 4
  страницы (`about.html`, `artists.html`, `booking.html`, `location.html`)
  остаются как есть, без изменений, миграция на React — отдельная будущая
  задача.
- Видео-фон — AI-сгенерированный короткий ч/б клип в стилистике мокапов
  (не чужой CloudFront-файл из спека).
- Логотип и навигация в шапке — существующие (корона+YB, Главная/О нас/
  Артисты/Расположение), не логотип-плейсхолдер и не пункты меню из спека.
- Виджет "Now Playing" — переносится как есть по вёрстке/интеракции, но с
  треком из ростера YOUNGBLOOD и завязкой на существующую Web Audio API
  демо-бит логику вместо реального аудиофайла.
- Cart-кнопка в шапке (нерелевантна для студии) — заменяется на пилюлю с
  иконкой `Phone` и номером `+7 (999) 123-45-67` (тот же, что в футере).
- Сборка и деплой — через GitHub Actions (переключаем источник GitHub Pages
  с "Deploy from branch" на "GitHub Actions"). Это меняет настройку
  репозитория — делается отдельным явно подтверждённым шагом.

## Архитектура

- Новая папка `app/` в корне репозитория — самостоятельный Vite-проект
  (React + TypeScript + Tailwind CSS), не трогает существующие файлы в
  корне (`index.html`, `about.html`, `assets/` и т.д. остаются, но текущий
  корневой `index.html` будет **заменён** результатом сборки `app/` в проде
  — см. workflow ниже).
- `.github/workflows/deploy.yml`: на push в `master`/`main`
  1. `cd app && npm ci && npm run build` → `app/dist/`
  2. Собирает публикуемый артефакт: `app/dist/*` (главная страница и её
     ассеты) + `about.html`, `artists.html`, `booking.html`, `location.html`,
     `404.html`, `.nojekyll`, `assets/` из корня (нетронутые статические
     страницы и их текущие стили/скрипты)
  3. Деплоит артефакт через `actions/deploy-pages`
- Итог на проде: `/` — новый React-hero, остальные страницы — прежние
  статические HTML, ссылки между всеми страницами продолжают работать,
  так как в опубликованном каталоге всё лежит рядом.
- Vite-конфиг: `base: './'`, `build.assetsDir: 'app-assets'` (чтобы не
  конфликтовать с существующей папкой `assets/`, которую используют
  остальные 4 страницы).
- Локальная разработка: `cd app && npm run dev` — обычный Vite dev-сервер,
  не требует локального веб-сервера для статики (тот нужен только для
  предпросмотра остальных 4 страниц, как и сейчас).

## Компоненты (`app/src/`)

- **`BoomerangVideoBg.tsx`** — переносится по спеку почти без изменений:
  проигрывает видео один раз (muted, playsInline, crossOrigin="anonymous"),
  захватывает кадры в offscreen-канвасы (макс. ширина 960px),
  `requestVideoFrameCallback` с фолбэком на `requestAnimationFrame`, по
  окончании — пинг-понг луп на 30fps. Источник —
  `app/public/hero-loop.mp4` (см. "Видео-фон" ниже). Контейнер
  `absolute inset-0 z-0 scale-[1.08] origin-center overflow-hidden`.
- **`Header.tsx`** — логотип: существующий инлайн-SVG (корона) + текст
  `YOUNGBLOOD` шрифтом `Rubik Wet Paint` (как в текущем `.brand`).
  Навигация (скрыта на мобильных): Главная / О нас / Артисты /
  Расположение — ссылки на соответствующие `.html`. Справа: белая
  pill-кнопка с жёлтым квадратом-иконкой (`Phone`, lucide-react, size 14)
  и текстом `+7 (999) 123-45-67` (на маленьких экранах — просто иконка),
  `href="tel:+79991234567"`; мобильный тоггл-меню — `liquid-glass`
  квадрат с `Menu`/`X` (lucide-react, size 18), мобильный дропдаун —
  `liquid-glass` панель с теми же 4 ссылками + `booking.html`.
- **`Hero.tsx`** — контент:
  - Badge (`.liquid-glass`, delay-1): `СТУДИЯ ЗВУКОЗАПИСИ · МОСКВА`
  - Заголовок (delay-2, шрифт `Anton`/`--font-display`, как в мокапе
    карточки "ЗАПИСАТЬСЯ", где эта же фраза набрана жирным условным
    капсом, а не кистью): `твой звук.` / `твои правила.`
  - Подтекст (delay-3): `Запись, сведение и продакшн для тех, кто
    формирует новую волну.`
  - Кнопки (delay-4): основная (`bg-white`) — `Записаться` →
    `booking.html`; вторая (`.liquid-glass`) — `Наши артисты` →
    `artists.html`
- **`NowPlayingWidget.tsx`** (bottom-right, delay-5) — карточка трека
  (`FLEXY — Демо-бит`), прогресс-бар и play/pause запускают ту же
  генерацию демо-бита через Web Audio API, что уже используется в модалке
  артиста на `artists.html` (переиспользуем существующую функцию из
  `main.js`, портированную в TS-модуль). Кнопки prev/next переключают
  между 2–3 артистами ростера. Heart-кнопка — чисто визуальный тоггл
  (`fill-current`), без бэкенда.
- Иконки — только `lucide-react`.

## Цвет, шрифты, эффекты

- Акцентный цвет везде вместо `blue-700` → `var(--yellow)` (`#FFD600`).
- `Helvetica Regular` (внешний CDN-шрифт из спека) не используется —
  оставляем существующие шрифты проекта: `Inter` (текст), `Rubik Wet
  Paint` (логотип/брендинг), `Anton` (крупные заголовки, если понадобится
  в hero).
- `.liquid-glass` и fade-up анимации (включая `animation-fill-mode:
  backwards` и обязательное условие не ломать `backdrop-filter`) —
  переносятся из спека без изменений, это чисто техническая механика,
  независимая от цветовой темы.
- Общий фон под видео — `var(--black)`, как сейчас.

## Видео-фон

Короткий (3–5 сек) зацикленный чёрно-белый клип в стилистике мокапов:
студия/граффити-стена, лёгкое атмосферное движение (дым, свет, пыль в
луче прожектора). Генерируется отдельным шагом через доступный
инструмент AI-видео, конвертируется в mp4 (~960px по ширине, без звука),
кладётся в `app/public/hero-loop.mp4`. Если генерация окажется
недоступна или результат не подойдёт — временный фолбэк: статичный
CSS-фон (текущий `.hero` background), `BoomerangVideoBg` при этом
остаётся полностью готовым компонентом, просто без реального видео на
входе.

## Обработка ошибок / edge cases

- `requestVideoFrameCallback` недоступен (Safari < 16, некоторые
  мобильные браузеры) → фолбэк на `requestAnimationFrame`, поведение
  визуально не отличается.
- Видео не загрузилось / автоплей заблокирован браузером → показываем
  статичный CSS-фон текущего `.hero` вместо пустого чёрного экрана.
- `prefers-reduced-motion: reduce` → fade-up анимации отключаются (как
  в текущем спеке), boomerang-видео не останавливаем принудительно (это
  фон, а не декоративная анимация текста), но обычный `<video>`-цикл
  (без ping-pong захвата) остаётся приемлемым фолбэком.
- Мобильные экраны — навигация и виджет уже описаны с адаптивными
  брейкпоинтами (`sm:`, `md:`) по спеку.

## Тестирование

- Ручная проверка в браузере (`npm run dev`) на десктопном и мобильном
  вьюпорте: видео проигрывается, зацикливается пинг-понгом, анимации
  входа отрабатывают один раз, liquid-glass не ломается после анимации,
  ссылки шапки/кнопок ведут на правильные существующие `.html`-страницы.
- Проверка сборки: `npm run build` в `app/` проходит без ошибок,
  `npm run preview` показывает корректный результат.
- Проверка деплоя: после настройки GitHub Actions — тестовый push в
  ветку, проверка что Pages деплоит и главная, и остальные 4 страницы
  корректно (ссылки между страницами не 404-ят).
- Автоматизированных unit/e2e тестов для этой итерации не заводим
  (масштаб — один visual-компонент), возможный e2e-скрин-тест — вопрос
  будущей итерации при миграции всего сайта.

## Явно вне рамок этой итерации

- Миграция `about.html`, `artists.html`, `booking.html`, `location.html`
  на React — отдельная будущая задача/спек.
- Замена CSS-заглушек (`.photo-tile`) на реальные/AI-фото — отдельная
  ранее обсуждённая задача, не входит сюда.
